# 实现约定

## 数据流

`GLFW drop → 捕获地面交点 → CPU 工作线程导入 → ImportedAsset → 分批 GPU 上传 → AssetHandle → SceneObject`

导入线程只操作 CPU 数据，不调用 Vulkan 或 ImGui。路径规范化后作为缓存键；同一文件仅执行一次导入和上传。多文件批次保持输入顺序，只有前一个资产的包围盒可用后才计算下一个位置。场景文件恢复复用同一资产请求入口，不重复覆盖保存的变换。

`ImportedAsset` 包含源路径、图像、PBR 材质、网格和节点层级；网格保留局部空间，节点含父索引及局部/世界矩阵。资产包围盒包含节点变换。世界对象的最终矩阵为对象变换乘资产节点世界矩阵；拖放偏移使用资产包围盒的底部中心。

## 渲染与资源寿命

Vulkan 1.3 单 graphics/compute/present queue；双帧命令池、fence、acquire semaphore，以及按交换链图像分配的 present semaphore。CPU 写入 uniform、实例和上传缓冲之前等待该帧 fence。共享离屏目标通过 Synchronization2 屏障在提交间排序。

每帧最多复制 16 MiB 模型数据。图片按完整行切片上传，最后一次上传完成后生成 mipmap 并转入采样布局。GPU 上传结束的提交完成后才允许场景使用对应资源。删去最后一个对象引用后，资源进入待释放列表，直到使用它的提交完成；CPU 资源随引用释放。

普通材质使用传统描述符集合：全局 uniform/实例 SSBO/IBL/阴影为 set 0；材质 uniform 和 8 个贴图槽为 set 1。相同图像按线性与 sRGB 用途分别缓存。缺失贴图使用白色或平面法线。对象 ID 存放于实例数据中。

通道顺序：方向光阴影 → HDR 背景和不透明物体 → 排序透明物体 → 按需对象 ID → 色调映射及选中轮廓 → ImGui。HDR 颜色和深度使用 4× MSAA，颜色 resolve 后进入色调映射。选中轮廓由完整对象 ID 图像生成；仅拾取且无选中轮廓时，使用 1 像素 scissor。点击像素复制到帧专用读回缓冲，fence 完成后返回对象 ID。

实例按资产、材质、网格和镜像状态分组；视锥剔除基于变换后的子网格包围盒；透明物体按距离从远到近绘制。方向光阴影包含场景中的所有不透明/裁剪模型，避免镜头外物体的影子丢失。

## 场景文件与失败处理

场景版本为 `1`，包含 `objects`、`camera` 和 `environment`。模型及 HDR 路径相对场景文件目录解析。对象保存 ID、名称、源文件、position/rotation/scale、visible；GPU handle 为运行时数据，不序列化。

读取先构建并验证完整临时 Scene，再替换当前场景。非法 JSON、未知版本、重复 ID、非有限数和零缩放拒绝读取。缺失模型保留占位对象和错误说明；重新定位通过原对象 ID 发起新导入。

保存写入同目录临时文件，写入成功后使用 Windows `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)` 替换。HDR 解码在后台执行，成功创建 IBL 后更新当前环境路径；失败保持已有环境，连续请求采用最后一次请求。

## 扩展位置

新增模型格式优先映射到 `ImportedAsset`，不要直接创建 GPU 对象。新增 glTF 必需扩展时，先加入真实实现和回归样例，再更新扩展白名单。新增材质槽需要同步更新 C++ uniform 布局、描述符布局与 GLSL 定义。

当前保持单文件渲染器实现，不引入通用 render graph 或 ECS。后续如加入多灯光、光追或 LOD，再依据实际数据流拆分渲染通道和资源管理。
